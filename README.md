# Машинно обучение за откриване на мрежови атаки (CIC-IDS2017)

Експериментално изследване на ефективността на четири алгоритъма за машинно обучение за откриване на четири
мрежови атаки върху публичния набор данни **CIC-IDS2017** (Canadian Institute for Cybersecurity, UNB).
Екип от двама – всеки член изследва 2 атаки с 2 алгоритъма, общо **8 модела**:

| Член | Атаки | Алгоритми |
|---|---|---|
| Член 1 | DDoS (LOIC), PortScan (Nmap) | Random Forest, k-NN |
| Член 2 | DoS (Hulk, GoldenEye, Slowloris, Slowhttptest), Brute Force (FTP/SSH-Patator) | MLP, логистична регресия |

Всеки модел е конвейер:

```
sign(x)·ln(1+|x|)  →  StandardScaler  →  PCA (99 % дисперсия, 78 → 22–24)  →  класификатор
```

## Резултати (оперативна фаза, 30 % невиждани потоци)

| Модел | TP | TN | FP | FN | Precision | Accuracy | Sensitivity | µs / поток |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| DDoS · Random Forest | 38 395 | 28 525 | 4 | 10 | 99,990 % | 99,979 % | 99,974 % | 3,3 |
| DDoS · k-NN | 38 398 | 28 524 | 5 | 7 | 99,987 % | 99,982 % | 99,982 % | 62,9 |
| PortScan · Random Forest | 27 234 | 36 989 | 0 | 12 | 100,000 % | 99,981 % | 99,956 % | 2,1 |
| PortScan · k-NN | 27 242 | 36 989 | 0 | 4 | 100,000 % | 99,994 % | 99,985 % | 62,6 |
| DoS · MLP | 57 809 | 125 049 | 48 | 301 | 99,917 % | 99,810 % | 99,482 % | 2,6 |
| DoS · логистична регресия | 57 678 | 123 956 | 1 141 | 432 | 98,060 % | 99,141 % | 99,257 % | 2,0 |
| Brute Force · MLP | 2 738 | 123 782 | 26 | 8 | 99,059 % | 99,973 % | 99,709 % | 2,7 |
| Brute Force · логистична регресия | 2 734 | 123 763 | 45 | 12 | 98,381 % | 99,955 % | 99,563 % | 2,1 |

* Член 1: при DDoS разликата RF / k-NN не е статистически значима (McNemar p = 0,754); при PortScan k-NN е
  значимо по-чувствителен (p = 0,008). Random Forest детектира ~23 пъти по-бързо и има настройваем праг.
* Член 2: MLP е значимо по-точен от логистичната регресия и при двете атаки (p < 0,001); при DoS линейният модел
  прави 4,5 пъти повече грешки → границата между класовете е нелинейна.

Пълният анализ е в текстовия документ на изследването (предаден отделно), раздел 5.

## Кръстосана проверка с външен набор данни – InSDN

За да се провери дали моделите работят извън мрежата, в която са обучени, е използван независим набор:
**InSDN** (University College Dublin, 2020; SDN мрежа с ONOS, Open vSwitch и Mininet; 343 889 потока, CICFlowMeter;
лиценз CC BY-NC 4.0). Колоните са съпоставени с имената от CIC-IDS2017 (`src/external_data.py`), без премахване.

| Експеримент | Резултат |
|---|---|
| А – 8-те модела от CIC-IDS2017, приложени без промяна | Sensitivity ≈ 0 % (16 открити от ~151 000 атакуващи потока), почти без фалшиви тревоги |
| Б – същите алгоритми, параметри и обработка, обучени върху 70 % от InSDN | Accuracy 99,49–99,99 % върху останалите 30 % |

Причини: други разновидности на атаките (DDoS – ICMP наводнение; Brute Force – срещу уеб вход), друга версия на
CICFlowMeter, която определя посоката на потока различно (98,7 % от DDoS потоците в InSDN са без пакети в права
посока, а в CIC-IDS2017 – 0 от 1 469 757), и виртуална мрежа с милисекундни потоци. В експеримент Б
хиперпараметрите не са търсени наново – взети са от CIC-IDS2017. Извод: методът се пренася, обученият модел – не;
всеки детектор (и в център за данни) трябва да се обучава с трафик от своята мрежа.

```bash
python src/step5_external_test.py
```

## Правила при обработката на данните

* **Нито една колона не е премахната** – всички 79 колони (78 характеристики + `Label`) се запазват.
  `src/action_log.py` спира изпълнението, ако някоя стъпка намали броя на колоните.
* Редукцията на размерността е чрез **PCA** (всяка компонента е линейна комбинация от всички 78 характеристики).
* `NaN`/`Infinity` в `Flow Bytes/s` и `Flow Packets/s` (само при `Flow Duration = 0`) се **преизчисляват**
  с продължителност 1 µs – без изтриване на редове.
* Пълните дубликати се премахват (2 633 – DDoS, 72 353 – PortScan, 81 909 – DoS, 24 065 – Brute Force), за да
  няма еднакви записи в обучаващото и тестовото множество.
* В DoS файла се отстраняват 11 потока Heartbleed (друга атака) и 96 противоречиви записа (еднакъв вектор на
  характеристиките, етикет и BENIGN, и DoS). Колоните остават 79.
* Всички трансформации се обучават само върху обучаващото множество (scikit-learn `Pipeline`).

Всяко действие е записано в `logs/data_actions_log.md` (брой редове и колони преди/след).

## Обучени модели

Папка `models/` съдържа осемте обучени модела – целият конвейер (трансформация, стандартизация, PCA и
класификатор), записан с `joblib`. SHA-256 сумата на всеки файл е в `logs/training_log.md`.

| Файл | Атака | Алгоритъм | Размер |
|---|---|---|---:|
| `DDoS_RF.joblib` | DDoS | Random Forest | 1,1 MB |
| `DDoS_KNN.joblib` | DDoS | k-NN | 25,5 MB |
| `PortScan_RF.joblib` | PortScan | Random Forest | 0,2 MB |
| `PortScan_KNN.joblib` | PortScan | k-NN | 24,4 MB |
| `DoS_MLP.joblib` | DoS | MLP | 0,1 MB |
| `DoS_LR.joblib` | DoS | логистична регресия | 0,02 MB |
| `BruteForce_MLP.joblib` | Brute Force | MLP | 0,1 MB |
| `BruteForce_LR.joblib` | Brute Force | логистична регресия | 0,02 MB |

Моделите са обучени със scikit-learn 1.6.1 и се зареждат със същата версия (`requirements.txt`). Моделите k-NN
са големи, защото съхраняват всички обучаващи вектори. Форматът `joblib` използва pickle – зареждайте само
файлове от източник, на който имате доверие.

## Структура

```
src/
  config.py                пътища, константи, атаки, алгоритми, разпределение в екипа (TEAM)
  download_data.py         изтегляне + SHA-256 проверка на CIC-IDS2017
  action_log.py            дневник на действията върху данните и текстов лог
  preprocessing.py         почистване, разделяне 70/30, конвейер (log → scaler → PCA → модел)
  plot_style.py            единен стил на фигурите
  step1_prepare_data.py    ФАЗА 1: профил на данните, почистване, фигури p1_*
  step2_dimensionality.py  ФАЗА 1: PCA, експеримент с брой компоненти, фигури p2_*
  step3_train_evaluate.py  ФАЗА 2: GridSearchCV + 5-fold CV, оперативен тест, модели *.joblib
                           (--only DoS,BruteForce – само моделите на дадени атаки)
  step4_figures.py         ФАЗА 2: фигури p3_* (матрици на грешките, метрики, ROC, време)
  overfitting_check.py     проверка за преобучение (обучение / кръстосано валидиране / тест)
  external_data.py         външният набор InSDN: съпоставяне на колоните с CIC-IDS2017
  step5_external_test.py   кръстосана проверка: пренос на моделите (А) и обучение върху InSDN (Б), фигури p4_*
  detect.py                оперативна детекция върху нов CSV с потоци
  run_all.py               целият експеримент наведнъж
models/    8-те обучени модела (*.joblib)
results/   figures/ (PNG), tables/ (CSV), metrics.json, phase1_summary.json, dimensionality_summary.json,
           overfitting_check.json, external_insdn.json
logs/      data_actions_log.md, training_log.md, experiment_log.txt
```

## Изпълнение

```bash
pip install -r requirements.txt
python src/download_data.py
python src/run_all.py
```

Оперативна детекция с обучен модел:

```bash
python src/detect.py --model models/DDoS_RF.joblib --input data/processed/DDoS_clean.csv --limit 20000
```
